# SAPI 小爱离线唤醒器设计

## 目标

用 Windows 自带的简体中文语音识别器替换 Picovoice Porcupine。程序在后台持续监听固定短语“你好小爱”，识别成功后让微软商店版小爱同学进入聆听状态。运行期间不依赖云端 API、账户或 AccessKey。

## 范围

- 使用本机已安装的 `Microsoft Speech Recognizer 8.0 (zh-CN)`。
- 仅识别“你好小爱”，不做通用语音转文字。
- 复用原项目的 `xiaoai.exe` 来触发小爱同学进入聆听状态；不得用普通商店应用启动入口代替。
- 支持开机启动。
- 不提供设置窗口、托盘菜单、自动更新或第三方模型。
- 以空闲资源占用和文件数量最小为项目级约束。

## 结构与数据流

实现为一个面向 Windows 的小型 C# 可执行程序：

1. 启动时通过命名互斥量保证只有一个实例。
2. 选择 `zh-CN` SAPI 识别器并连接默认麦克风。
3. 加载仅含“你好小爱”的精确语法，进入连续异步识别。
4. 收到识别结果后检查置信度和冷却时间。
5. 条件满足时运行同目录下的 `xiaoai.exe`。
6. `xiaoai.exe` 负责向商店版小爱同学发送聆听触发：未运行时启动并聆听，已运行时重新进入聆听。
7. 短暂等待小爱窗口出现，将其放到主显示器工作区右下角，右侧和底部各留 `12` 像素。
8. 使用 Windows 原生窗口位置变化事件保持右下角锚定；只有窗口移动或改变尺寸时才工作，不做永久定时轮询。

## 聆听触发依据

已在本机对两条启动路径做隔离 A/B 验证：

- 普通商店应用入口仅打开小爱窗口，界面显示彩色静态语音球。
- 原项目 `xiaoai.exe` 启动后，界面切换为语音波形并显示聆听倒计时，随后能识别环境语音。
- 小爱已经运行时再次执行 `xiaoai.exe`，仍会重新触发聆听。

因此实现必须调用原 `xiaoai.exe`，不能直接运行包内 `Xiaoai.exe` 或 `shell:appsFolder` URI。

## 资源与文件约束

最终只新增 `SapiXiaoai.exe` 一个文件。程序复用原目录已有的 `xiaoai.exe` 和 `set.ini`，不再创建第二个配置文件。`set.ini` 只读取灵敏度：

```ini
[settings]
sensitivities = 0.75
```

- `sensitivities` 必须在 `0.0` 到 `1.0` 之间；缺失或无效时使用 `0.75`。
- 冷却时间固定为 `5` 秒，窗口边距固定为 `12` 像素，避免增加无必要配置。
- 使用单个固定短语语法；不加载通用听写语法。
- SAPI 和窗口监听均使用事件回调；除等待小爱窗口出现的短时重试外，不创建轮询线程。
- 窗口出现后用 WinEvent 监听移动和尺寸变化，已经位于目标坐标时不调用 `SetWindowPos`，避免回调循环。
- 不设置始终置顶，不持续抢占前台焦点。

## 错误处理

- 找不到中文识别器、默认麦克风或 `xiaoai.exe` 时，显示一次明确错误并退出。
- `xiaoai.exe` 启动失败时显示错误，但继续监听，允许下次重试。
- 第二个实例启动时直接退出，不弹出重复提示。

## 验证

- 启动后确认进程持续运行且没有 Picovoice 网络连接。
- 说“你好小爱”，确认小爱界面出现语音波形/倒计时，并能接收紧随其后的口述内容；仅出现窗口不算通过。
- 在冷却期内连续说两次，确认不会重复触发。
- 确认小爱窗口固定在主显示器可用工作区右下角，任务栏不会被遮挡；回答导致窗口高度变化时仍保持右下角对齐。
- 播放普通中文语音，观察是否误触发；必要时只调整 `set.ini` 的 `sensitivities`。
- 空闲运行时确认不存在持续定时轮询、Picovoice/Python 模块或 Picovoice 网络连接。
- 暂时移走 `xiaoai.exe`，确认错误提示明确且程序不会崩溃。
- 启动第二个实例，确认只保留一个后台进程。

## 交付方式

只把新程序 `SapiXiaoai.exe` 放入原项目目录，并把现有 `set.ini` 的 `sensitivities` 调整为 `0.75`。验证通过后，可用启动文件夹中的普通快捷方式实现开机自启，不再依赖原来的 `VoiceXiaoai.exe`、Porcupine 模型、Python 运行时或 Picovoice AccessKey。
